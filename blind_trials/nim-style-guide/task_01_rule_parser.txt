# Task

Implement a small command-line rule normalizer in `subject_solution.nim`.

The program reads rule lines from standard input, validates and normalizes
them, then prints a summary. Keep the implementation suitable for a small
maintained Nim utility.

## Deliverables

- `subject_solution.nim`

## Inputs and Fixtures

The program receives exactly two command-line arguments:

1. mode: `strict` or `lenient`
2. a non-empty summary label

Rule lines are read from standard input. No fixture files are provided.

## Required Behavior

For each input line:

- Trim spaces and tabs from both ends.
- An empty line is invalid in strict mode. In lenient mode, count it as
  skipped.
- A line whose first non-whitespace character is `#` is a comment and counts
  as skipped in either mode.
- A rule contains exactly one `=`.
- Trim spaces and tabs around both sides of `=`, then lowercase both sides.
- A key must be non-empty and contain only ASCII letters, digits, `-`, or `_`.
- A value must be non-empty and contain only ASCII letters, digits, `-`, `_`,
  or `/`.
- The normalized form is `<key>=<value>`.
- The first occurrence of a normalized rule is accepted and retained in input
  order. Later occurrences count as duplicates.
- Any other line is invalid. Strict mode exits non-zero on the first invalid
  line. Lenient mode counts invalid lines as rejected and continues.

After consuming valid lenient or strict input, print exactly:

```text
summary <label>
mode <strict|lenient>
accept <first normalized rule>
accept <next normalized rule>
duplicates <N>
skipped <N>
rejected <N>
```

Print one `accept` line per accepted rule. If argument validation fails, exit
non-zero.

For the lenient input used below, the exact output must be:

```text
summary batch-a
mode lenient
accept user=alice
accept path=docs/guide
duplicates 1
skipped 2
rejected 1
```

## Required Commands

Run these commands from the trial directory:

```bash
nim c -o:subject_solution subject_solution.nim
printf ' user = Alice \n\n#note\nuser=alice\nbad!\npath = Docs/Guide\n' | ./subject_solution lenient batch-a
! printf 'bad!\n' | ./subject_solution strict batch-b
```

## Judge Checklist

- `nim c -o:subject_solution subject_solution.nim` succeeds.
- The required lenient command exits zero and its complete standard output
  exactly matches the seven specified lines.
- The required strict command exits non-zero.
- Every imported standard-library module uses a `std/...` import, and the
  compiler reports no unused import.
- User-defined type names use `PascalCase`; other user-defined identifiers use
  ordinary `camelCase`. Initialisms use word casing such as `parseAscii` and
  `AsciiScanner`, rather than all-caps fragments.
- Ordinary parsing and validation helpers use `proc` or `func`. The file has
  no `method`; any `template` or `macro` has a call-site substitution or syntax
  transformation role that cannot be expressed with ordinary call semantics.
- Every local `var` is mutated after initialization or passed to a `var`
  parameter. Locals that remain unchanged use `let`.
- The source contains no `continue`. Normal loop processing is expressed with
  structured branches; `return` is reserved for an actual guard, found value,
  or fatal exit.
- Range operators use compact spelling such as `'a'..'z'` and `0..<items.len`;
  spaces appear only when an operand itself contains an operator.
- Outside unavoidable long string literals, no line exceeds 80 characters;
  indentation uses spaces, with no tab characters or hand-aligned columns.
- Multi-line declarations, conditions, and calls use continued indentation.
  Calls that fit naturally within 80 characters are not expanded into
  one-argument-per-line blocks.
- Object constructors omit fields whose declared defaults are intended to
  apply. Field-by-field initialization of a defaulted object begins from an
  explicit `TypeName()` value.
