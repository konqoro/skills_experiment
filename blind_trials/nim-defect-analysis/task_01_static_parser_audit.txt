# Task

Review a small Nim HTTP request router for reliability and correctness defects.
This is a static review plus targeted confirmation task, not a fuzzing task.

## Deliverables

Create:

- `review_report.md`
- any minimal reproducers you need under `reproducers/`

## Inputs and Fixtures

The router source is staged at:

```text
fixtures/request_router.nim
```

Treat raw request strings passed to `dispatch` as externally-controlled.

## Required Behavior

Your report must:

- identify reliability and correctness defects only
- classify each finding as `CONFIRMED`, `TRACED`, `SUSPECTED`, or `FALSE_POSITIVE`
- include a static trace from external input to the failure
- include expected behavior, actual behavior, and impact assessment
- include exact commands and observed output for every `CONFIRMED` finding
- avoid fuzzing or long-running search

If you think a suspicious path is blocked by a guard, classify it as
`FALSE_POSITIVE` and explain the guard.

## Required Commands

Run any reproducer commands you include in `review_report.md` from the trial
directory.

At minimum, the router itself must compile:

```bash
nim c --nimcache:nimcache fixtures/request_router.nim
```

## Judge Checklist

- `review_report.md` exists.
- The report identifies the `parseVersion` crash on a version string with no dot (e.g. `X-Api-Version: 2`) as a `CONFIRMED` finding.
- The report explains that `parseVersion` splits on `.`, accesses `parts[1]`, and raises `IndexDefect` when there is no dot.
- The report explains that `dispatch` catches `ValueError` but not `IndexDefect`/`Defect`, so the crash escapes the handler.
- A reproducer under `reproducers/` exists and can be run with `nim c -r`.
- Running the reproducer demonstrates the `IndexDefect` crash or catches and prints the `IndexDefect` evidence.
- The report identifies the `hasHeader` case-sensitivity bug: `hasHeader` lowercases the search name but compares against the stored name's original case, so headers stored with mixed case (e.g. `X-Trace-Id`) do not match a search for the same name in a different case.
- The report identifies the invalid `Content-Length` bug: `getContentLength` calls `parseSaturatedNatural` which returns `0` for non-numeric input, and the function returns `-1` (meaning "no header") instead of rejecting the invalid value, so an invalid `Content-Length` bypasses the body-size check.
- The report classifies the `maxHeaders` limit as `FALSE_POSITIVE` or does not report it as a defect, because `parseRequest` raises `ValueError` when `headers.len >= maxHeaders` and `dispatch` catches `ValueError`.
- The report classifies the `maxValueLen` limit as `FALSE_POSITIVE` or does not report it as a defect, because `parseRequest` raises `ValueError` when `h.value.len > maxValueLen` and `dispatch` catches `ValueError`.
- The report does not rely on fuzzing as the confirmation method.
- The report includes at least one concrete remediation direction per confirmed finding.
